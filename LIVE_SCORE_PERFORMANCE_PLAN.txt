Implementation changes (cricket-api):
1. Status-aware TTL middleware:
   function liveTtl(req, res, next) {
     const isLive = req.query.status === 'live' || res.locals.matchIsLive
     res.locals.cacheTtl = isLive ? 5 : 120
     next()
   }

2. Stale-while-revalidate pattern:
   - Return cached value immediately (fast response)
   - Trigger background refresh if age > TTL
   - Next caller gets fresh data
   - Prevents slow provider latency from blocking users

3. In-flight request dedupe (per cache key):
   const inflight = new Map()
   async function fetchWithDedup(key, fetchFn) {
     if (inflight.has(key)) return inflight.get(key)
     const p = fetchFn().finally(() => inflight.delete(key))
     inflight.set(key, p)
     return p
   }

4. Provider timeout:
   - Hard timeout: 3000ms (currently may be higher)
   - On timeout: return stale cache if available, else error
   - Log timeout events for monitoring

5. Status-based polling differentiation:

   - Flutter reads this to adjust its own poll interval

6. Admin TTL controls (optional, add to /app/config):

PHASE C — WebSocket/SSE (Future, not now)
-------------------------------------------
WebSocket would allow push instead of poll:
  - Server pushes score update when provider data changes
  - Client receives, updates UI instantly
  - Removes need for client polling

Cricbuzz does not provide WebSocket. Backend would need to:
  1. Poll provider at 3s
  2. Detect change (hash comparison)
  3. Push to connected clients via WebSocket/SSE

This is a significant backend change. Plan separately.
Do NOT implement in current batch.
