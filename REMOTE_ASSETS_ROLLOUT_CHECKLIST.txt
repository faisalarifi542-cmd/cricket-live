  cd /path/to/cricket-api
  npm run migrate

  safe to re-run, never drops/overwrites existing data.
- No other tables touched by this change.
- Verify table exists after:
    mysql -u <user> -p <db> -e "DESCRIBE app_assets;"

  created_at, updated_at. Unique key (asset_key, theme).

================================================================================
6. ROLLBACK STEPS
================================================================================
Fastest (no deploy): in Admin /assets, toggle the asset OFF or Revert it.
App falls back to bundled image on next cold start. Zero risk.

Server rollback (if endpoint misbehaves):
- GET /app/assets failing does NOT break app — RemoteAssetsService swallows
  errors, app uses bundled. So no urgent rollback needed.
- To fully disable: revert src/routes/app.js (/app/assets handler) +
  src/admin/index.js (assets route registration) and redeploy.
- app_assets table can stay — harmless if unused. No need to drop.

Code rollback: git revert the Remote Assets commit. Bundled assets untouched,
so app keeps working identically to pre-MVP.

8. WHICH ASSETS MUST STAY BUNDLED FOREVER
================================================================================
Never make these remote-only (must always work offline / first paint):
- App icon / launcher icon.
- Splash screen image.
- Brand logo shown on first frame / loading state.
- Any icon used in offline/error cards (e.g. no-connection illustration).
- Tab bar / nav icons, status icons (live/upcoming/finished), ball-by-ball
  glyphs — small, functional, must never flicker or 404.
- Team logo fallback placeholder (initials renderer).

These are functional UI, not decorative. Remote swap = risk of blank/wrong glyph.
