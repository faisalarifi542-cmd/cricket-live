2. CONFIRMED CRITICAL ISSUES (proven from local code)
================================================================================

C1. [CONFIRMED] Committed fallback secrets in source.
    - cricket-api/src/config/index.js:35
        jwtSecret: env('JWT_SECRET', 'dev-secret-change-in-production')
      If JWT_SECRET is unset on the server, admin auth tokens are signed with a
      publicly known secret → full admin impersonation. Server env MUST override.
    - cricket-api/src/db/migrate.js:10
        DEFAULT_APP_API_KEY = 'csk_live_cricpro_app_8f3a2b1c9d'
      Same key is hardcoded in the Flutter app (lib/core/api/api_config.dart:apiKey
      default). A public app key is acceptable by design, but it is committed and
      shared, so it provides NO real gate unless paired with enforce-mode + other
      client checks.
    Risk if server does not override: CRITICAL. If server overrides: downgraded
    to LOW (cleanup). -> VERIFY on server.

C2. [CONFIRMED] Public API runs in 'monitor' mode by default.
    - cricket-api/src/lib/api-security.js:DEFAULT_MODE = 'monitor'
      In monitor mode, requests that would be blocked are logged but ALLOWED.
      Until the live app_settings.apiSecurityMode = 'enforce', the public API is
      open to any client. Intentional rollout choice, but must be flipped.
    -> VERIFY the live mode value.

3. CONFIRMED HIGH PRIORITY ISSUES
================================================================================

H1. [CONFIRMED] Duplicate legacy Flutter tree inside backend folder.
    Path: cricket-api/lib/  (e.g. core/network/api_client.dart imports dio,
    widgets/app_logo.dart + core/theme/app_theme.dart import google_fonts,
    core/utils/cricket_helpers.dart imports intl).
    - This is a SEPARATE, older Flutter app embedded under the Node backend.
    - It is not referenced by the real app (lib/) and its packages (dio,
      google_fonts, intl) are NOT in the real pubspec.yaml.
    - It inflates `flutter analyze` with hundreds of false errors and confuses
      tooling/reviewers.
    Recommendation: move/delete from the backend folder (do NOT do as part of
    this review — flagged only).

H2. [CONFIRMED] Two competing model layers in the real app.
    - lib/api_models.dart           (RankingEntry, normalizeOversText, team flag
                                      suffix logic, AppConfig, etc.)
    - lib/models/api_models.dart    (duplicate RankingEntry, normalizeOversText,
                                      same comments/logic)
    Both are imported in different places (e.g. rankings_screen.dart imports
    api_models.dart; api_response.dart lives under models/). Divergence is a real
    maintenance hazard — a fix applied to one will silently miss the other.
    Recommendation: consolidate to a single source of truth.

H3. [CONFIRMED] App ships a real-looking default API key + package name.
    - lib/core/api/api_config.dart: packageName default
      'com.example.cricpro_flutter' (placeholder bundle id) and apiKey default
      'csk_live_...'. If a production build forgets the --dart-define overrides,
      the app identifies as the example package with the shared key. -> VERIFY
      the release build injects real --dart-define values.

H4. [VERIFY/CONFIRMED-template] CORS default is wide open.
    - .env.example: CORS_ORIGIN=*
    - server.js registers dynamic CORS via corsOriginDelegate with
      credentials:true. With credentials:true a literal '*' origin is unsafe.
      The dynamic delegate reads api_allowed_origins from DB, so prod safety
      depends entirely on that table being populated and CORS_ORIGIN not being
      '*'. -> VERIFY live origin allowlist.
