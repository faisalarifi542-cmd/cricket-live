LIVE-LINE DATA CORRECTNESS FIX BEFORE SWR EXPANSION  (2026-06-12)
================================================================================

Tested real provider match live-line: /match/121774/live-line. Response 200 OK
but normalized data wrong: status "unknown" on a live match; latestBall.result
"0" while commentary said "1 run, to cover"; latestBall.key ended with NONE;
latestBallResult "0". Fixed normalization ONLY. No SWR expansion.

1. ROOT CAUSE
   - extractLatestBall() in src/providers/cricbuzz/client.js only understood the
     balls-map. On live matches the balls-map is frequently empty, so it fell to
     the commentary path. The commentary path NEVER parsed the run value out of
     natural-language text -- the only text rule was /no run/ -> 0. So "1 run,
     to cover" produced runs=0 and an empty result token.
   - buildLiveLineData() then derived latestBall.result from the event enum;
     with event NONE it used String(runs||0) = "0".
   - latestBallKey was built from the raw event enum, so it ended in "NONE"
     whenever the event could not be classified.
   - status used scoreDetails.status || header.status || 'unknown'. Cricbuzz
     often omits a clean status enum for in-progress matches, so it stayed
     "unknown" even though header.state was "In Progress".
