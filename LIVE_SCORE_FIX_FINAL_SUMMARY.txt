2. ROOT CAUSE OF STALE SCORE
----------------------------
PRIMARY (Flutter): backend emits status 'innings_break' between innings (and
rain/tea/drinks/stumps). Flutter isLive / _isLiveMatchData only counted 'live'/
'in_progress', so the match-detail poll timer was cancelled at the first innings
break and NEVER re-armed. When play resumed the app was no longer polling →
score stuck until pull-to-refresh (which restarts the timer). Matched the report
exactly.
SECONDARY (Flutter): a single transient network error in any poll loop cancelled
the timer permanently (no watchdog) — only foreground/pull restarted it.
MINOR (backend): /app/home via controlledFetch served up to 120s stale
(max(ttl*4,60)); featured/hero block only. SWR live routes were already fine
(8-20s physical cap). The SWR helper itself was NOT the cause.


3. BACKEND SWR/CACHE FIXES
--------------------------
- Live data types (homeData, liveMatches, matchDetail, liveLine, scorecard,
  commentary, overs) now use a short stale window min(max(ttl,5),15)s instead of
  max(ttl*4,60). Non-live keeps long stale (blip protection).
- Live envelopes get a tight physical Redis TTL (ttl+window+5s) so a dead live
  key cannot be served via the error-fallback for minutes.
- no-store/no-cache Cache-Control forced on every live endpoint (/app/home,
  /matches/live, /match/:id and its live sub-paths, /app/match/:id) — protects
  against Dio/OkHttp/CDN caching.
- Response headers added: X-Cache-Age-Ms, X-Stale (no Flutter model change —
  headers + meta only).
- Structured live-fetch log per live request for production visibility.
- SWR helper (redis.js) left UNCHANGED — it was already correct (background
  refresh writes back, if(fresh) guard prevents error-clobber, dedupe clean).


4. FLUTTER POLLING/REPOSITORY FIXES
-----------------------------------
- isLive treats innings breaks/stoppages as live → polling no longer stops mid
  match.
- Match-details: stop polling ONLY on terminal state (completed/abandoned/
  no_result/cancelled). Transient non-live reads keep polling.
- Self-healing recovery timer on home, matches, match-details: after a transient
  failure or a not-yet-live read, polling re-arms automatically with small
  backoff (no manual pull needed).
- Commentary + Overs tabs now auto-refresh during live polling (were frozen).
- Repository force path unchanged (already correct): forceRefresh drops memory
  cache and always hits network; auto-poll and pull-to-refresh use the same path.
- Tab selection + scroll offset preservation unchanged (already correct). No
  TabController recreation. setState only fires when payload actually changed.
