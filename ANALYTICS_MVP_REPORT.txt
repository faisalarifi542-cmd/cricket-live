2. DB TABLES ADDED
--------------------------------------------------------------------------------
analytics_events
  id          BIGINT PK AUTO_INCREMENT
  event_name  VARCHAR(60) NOT NULL
  device_id   VARCHAR(64)
  session_id  VARCHAR(64)
  payload     JSON
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP
  INDEX (event_name, created_at), (device_id, created_at),
        (session_id, created_at), (created_at)

analytics_devices   (deduplicated devices = approximate installs / first opens)
  device_id   VARCHAR(64) PRIMARY KEY
  first_seen  DATETIME DEFAULT CURRENT_TIMESTAMP
  last_seen   DATETIME DEFAULT CURRENT_TIMESTAMP
  app_version VARCHAR(20)
  platform    VARCHAR(10)
  os_version  VARCHAR(30)
  country     VARCHAR(5)
  INDEX (last_seen), (platform), (app_version)

Both use CREATE TABLE IF NOT EXISTS (idempotent — safe to re-run migrate).


3. ENDPOINTS ADDED
--------------------------------------------------------------------------------
PUBLIC (no login, no api-key):
  POST /analytics/events
    Body: { "events": [ { event_name, device_id, session_id, payload, ts } ] }
    - Batch capped at 50 events per request.
    - event_name validated against an allowlist; invalid events dropped silently.
    - payload sanitized: only short scalar fields kept (no nested objects, no
      long strings) — defends against PII / cardinality blowups.
    - Rate limited: 100 req/min (api_endpoint_rules group 'analytics_ingest').
    - Always returns 204 No Content (even on bad input) so clients never
      retry-storm.
    - app_open events also upsert analytics_devices (first_seen/last_seen +
      app_version/platform/os_version/country).

ADMIN (Bearer token + permission analytics.view):
  GET /admin/analytics/summary?from=&to=
      Active users (today/7d/30d), first opens/approx installs, sessions,
      screen views, match opens, live stream opens, quality selections,
      pull refreshes, retry-after-error count, top screens, top matches,
      top stream qualities, app versions, platforms.
  GET /admin/analytics/timeseries?metric=&from=&to=&granularity=day|hour
      metric: active_users | sessions | live_stream_opens | match_opens |
              screen_views | retry_after_error
      Returns [ { date, value } ].
  GET /admin/analytics/breakdown?dimension=&from=&to=
      dimension: app_version | platform | country | quality | screen


4. FLUTTER EVENTS TRACKED
--------------------------------------------------------------------------------
  app_open           app start (main.dart)         payload: app_version, platform
  session_start      app start / startSession()    payload: app_version
  screen_view        home, matches, match_details, live_player (once per open)
  match_open         Match Details open            payload: match_id
  live_stream_open   Live Player open              payload: match_id
  quality_selected   user changes HLS quality      payload: quality_code,
                                                             quality_label, match_id
  pull_refresh       manual pull-to-refresh (matches) payload: screen_name
  retry_after_error  shared CricOfflineCard retry  payload: error_type
  notification_open  notification click            payload: notification_type
  rewarded_unlock    premium stream unlocked by ad payload: match_id, stream_id

Anti-spam: screen_view fires once per screen open (guarded by init/match-id
checks), quality_selected only on actual change, pull_refresh only on manual
refresh (not auto-poll).

6. PRIVACY NOTES
--------------------------------------------------------------------------------
  - device_id: random hex (Random.secure()) generated on first launch, stored
    locally via SharedPreferences. NOT derived from IMEI / hardware / advertising
    id. session_id: random hex, regenerated each app start.
  - NO name, email, phone, IMEI, exact GPS, or any personal data is collected
    or stored. country is optional and only a coarse 5-char code (not stored
    unless explicitly provided in payload — currently not sent by the app).
  - Backend payload sanitizer drops nested objects and truncates strings, so the
    app cannot accidentally leak large/identifying values.
  - Analytics is fire-and-forget: never blocks the UI, never throws into
    navigation/loading. If the network or server fails, events stay queued
    (capped at 200) and the app continues normally.
  - Endpoint is public but write-only: it never returns admin data and never
    requires user login.

8. HOW TO VERIFY EVENTS ARE BEING STORED
--------------------------------------------------------------------------------
  a) Send a test event (from any machine — no api-key needed):
       curl -i -X POST https://api.webcrichd.co/analytics/events \
         -H 'Content-Type: application/json' \
         -d '{"events":[{"event_name":"app_open","device_id":"test-dev-1","session_id":"test-sess-1","payload":{"app_version":"1.0.0","platform":"android"}}]}'
     Expect: HTTP/1.1 204 No Content.

  b) Confirm rows in MySQL:
       SELECT COUNT(*) FROM analytics_events;
       SELECT event_name, created_at FROM analytics_events ORDER BY id DESC LIMIT 10;
       SELECT * FROM analytics_devices WHERE device_id = 'test-dev-1';

  c) Confirm via admin API (replace TOKEN with an admin Bearer token):
       curl -H 'Authorization: Bearer TOKEN' \
         'https://api.webcrichd.co/admin/analytics/summary'

  d) In the running app: open a match / live player / change quality, then wait
     up to 30s (or background the app) for the queue to flush, and re-check (b).

10. WHAT IS INTENTIONALLY NOT INCLUDED YET
--------------------------------------------------------------------------------
  - No real Play Store install data. "First Opens / Approx Installs" = distinct
    devices seen, NOT exact installs (labeled as such in API + UI).
  - No charting library on the admin panel (used lightweight CSS bars). A richer
    chart lib (recharts) can be added later.
  - No retention/cohort analysis, funnels, or per-user journeys.
  - No automatic data retention/trim job for analytics_events (table will grow;
    add a scheduled DELETE by created_at later if needed).
  - No country enrichment from IP (country field exists but is only populated if
    the client sends it; currently not sent).
  - ad_impression event is allowlisted on the backend but not yet wired in the
    app (reserved for when ad SDK callbacks are surfaced).
  - No realtime analytics (events are batched, up to 30s delay by design).
  - SWR / live-score work untouched (out of scope for this task).
