SPLIT STRATEGY — SAFEST MECHANISM: Dart `part` files
--------------------------------------------------------------------------------
  Many extractable widgets are PRIVATE (_Foo) and reference each other +
  screen-private helpers. Moving them to a normal sibling file would force
  renaming _Foo -> Foo (privacy break) + new imports = churn + regression risk.

  SAFEST: use `part` / `part of`. The screen file declares
      part 'widgets/<screen>_cards.dart';
  and the extracted file starts with
      part of '<screen>_screen.dart';
  -> private classes stay private, share the same library, ZERO behavior change,
     ZERO import churn elsewhere. Pure physical code move. Lowest regression risk.

  Rule: extract only PURE StatelessWidget chunks (and self-contained Stateful UI
  like _Countdown). Keep the screen State class + polling/data/nav in the main file.
