BUG 1 — Player/ranking pics show initials too early
================================================================================
ROOT CAUSE:
  - Rankings endpoint does NOT enrich entries w/ admin/provider player images.
    cricket-api/src/routes/rankings.js returns provider rows raw. Cricbuzz
    rankings HTML parse usually has NO image -> RankingEntry.imageUrl empty.
  - Flutter rankings_screen.dart:558 shows _Initial when image null/empty.
    Logic is correct (network-first, initials on null/error) — the DATA is missing.
  - server.js:251 enrichPlayerImages runs in preSerialization, but matches
    players by image-key/id; ranking rows lack a usable id->admin-image match.
FILES: cricket-api/src/routes/rankings.js, src/lib/player-images.js,
  lib/screens/rankings/rankings_screen.dart:558, lib/components.dart RankingAvatar,
  lib/api_models.dart RankingEntry (imageUrl exists ~1139/1182).
PROPOSED FIX (BE): in rankings route, enrich each entry — if entry has playerId,
  look up admin player image (player-images index) and provider headshot; set
  imageUrl with priority admin > provider > none. Keep initials fallback in FE.
RISK: MED (backend, provider-shape dependent). FE-only NOT enough.
NOTE: player stats in player_detail come from API (no hardcoded sample found).

BUG 6 — Match Details tab jumps / reverts
================================================================================
ROOT CAUSE A (Info->Live jump): _maybeApplyInitialTab (match_details_screen.dart
  :113-144) defers initial Live-tab switch to post-frame -> user sees Info first,
  then jump. Guarded by _userPickedTab/_initialTabApplied (runs once) — acceptable
  but jump is visible.
ROOT CAUSE B (tab reverts on tap): _restoreScrollAndTab:311-328 forces
  setState(tab=oldTab) where oldTab captured at poll/refresh START (line 271/204).
  If user taps a new tab while a 5s poll is mid-flight, post-frame restore reverts
  to the old tab. `tab` is a plain field NOT reset by rebuild, so forcing it back
  is unnecessary AND harmful.
FILES: match_details_screen.dart:113-144,200-238,261-309,311-328.
PROPOSED FIX (FE):
  B (primary): in _restoreScrollAndTab, only restore SCROLL offset, NOT tab. Drop
    the forced tab=oldTab (or guard with _userPickedTab). Tab persists naturally.
  A: set initial tab synchronously when first summary known (before first paint)
    if feasible; else accept minor. Lower priority than B.
RISK: LOW-MED (B is the real bug; isolate to scroll-only restore).
